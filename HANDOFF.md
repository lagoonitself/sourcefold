## What we're building

Sourcefold is an open-source (MIT), self-hosted research source collector. The owner collects sources for YouTube video research and feeds them into NotebookLM, Gemini and other tools.

- **Sources:** Grokipedia and Wikipedia articles, YouTube transcripts (captions YouTube already has, fetched as the InnerTube Android client; extension and desktop only), Reddit and Hacker News threads, Bluesky posts, PDFs and arXiv papers, any other web page (defuddle), Substack posts (free, plus paid posts the user subscribes to) and X posts (text only, threads kept as a tree). Bulk-paste 30–40 links of any mix. The README's "Supported sources" table is the user-facing list.
- **Format:** every source is stored as clean Markdown.
- **Organizing:** projects (for example "Cars", "Bikes"), each with its own groups inside groups, unlimited depth. A project is a top-level folder and a group is a folder inside one; the UI shows one project at a time. Each item lives in one group. Drag-and-drop to reorder or nest.
- **Reading:** clicking an item opens the original page (or signed link for uploaded images). The desktop app also includes an integrated Markdown reader for items with saved markdown text.
- **Drive:** holds the content. Supabase keeps only links, titles, metadata, folders and notes; article text and images are pushed to Drive right after saving and then cleared from Supabase. The **Save to Drive** button (and Ctrl+S) still pushes folder changes, renames, moves and deletes.
- **Desktop app:** fast native app for Windows and macOS. Runs signed in (mirrors web account data, content lives in Google Drive) or offline (local SQLite database and Markdown files on disk).
- **Chrome extension:** saves the page you're viewing into a chosen folder in one click. Auto mode routes saves to the desktop app when running, or directly to the web app.
- **Constraints:** $0 budget (free tiers only), desktop web app and desktop app (Windows, macOS), `ALLOWED_EMAIL` decides who signs in (a list, or `*` for anyone; the owner's deployment uses `*` since 2026-10-16 so friends can use it), each person's library is separate, search by title only.

## Current state

Waves 0 through 7 are deployed and working. Wave 8 (desktop app) is implemented across `apps/desktop` (Tauri v2 + React 19 + Rust + SQLite), `apps/extension` (Auto target resolution), and `apps/web` (`/desktop/connect` browser sign-in and token-auth routes).

- **Stack:**
  - Web app: Next.js 16 on Vercel.
  - Desktop app: Tauri v2 (React 19, Tailwind CSS v4, Rust, embedded SQLite via `rusqlite`).
  - Extension: Chrome (Manifest V3) built with WXT and React.
  - Backend: Supabase (Postgres with RLS, Auth with Google, Storage).
  - Storage: Google Drive API (`drive.file` only) for cloud content; local disk (`Documents/Sourcefold/`) for desktop offline content.
- **Local integration surface:** desktop app provides Chrome Native Messaging (`com.sourcefold.native`) and local HTTP loopback (`http://127.0.0.1:23456`).
- **Checks:** `npm run format:check`, `lint`, `typecheck`, Vitest test suites, and desktop Rust tests (`cargo test`) pass.

Lessons worth keeping:

- Vite must ignore `src-tauri/**` in `server.watch.ignored`, or `tauri dev` crashes on Windows with `EBUSY` when the Rust compiler locks binary and target files during compilation.
- The local loopback HTTP server on port 23456 must never send `Access-Control-Allow-Origin: *`. It strictly validates `Host` (`localhost` or `127.0.0.1`) and `Origin` (`chrome-extension://...`, `tauri://localhost`, etc.), responds with `Vary: Origin`, and restricts `/api/session` to extension origins. Only the pinned Sourcefold extension ID (`ccgpcafkpkdfndhamegkcafmhfpkajml`, from the `key` in `apps/extension/wxt.config.ts`, plus any in `SOURCEFOLD_EXTENSION_IDS`) is accepted. Any other installed extension could otherwise read the user's token. The extension also sends `X-Sourcefold-Extension: <its id>` on every local request.
- The desktop frontend and its Rust commands were first written by two separate agents, and their IPC contract didn't match (sign-in could never succeed). `apps/desktop/src/lib/__tests__/ipc-contract.test.ts` now checks every `tauriInvoke` call against `main.rs` and `commands/*.rs`. Keep it passing when adding commands.
- A Rust test once did a real native-host install and pointed Chrome's host at a test binary. Tests must never touch the real registry or manifest folders; the desktop app re-registers the host on startup.
- Token-authenticated API routes use `requireApiUser` with the Supabase admin client (`createAdminClient()`), which bypasses database RLS. Every query in those endpoints must explicitly filter by `user_id`. Database RPCs that rely on `auth.uid()` don't work with tokens and must receive `p_user_id` as an explicit parameter.
- The Google OAuth client in Supabase's Google provider must be the same client as the app's `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`. Otherwise Google refuses the token refresh with `unauthorized_client`, and reconnecting can never fix it. The app reports this case directly.
- A folder lists only its own items, not its subfolders' items. Users may think a save failed; the extension shows the full folder path and offers **Move here** for pages saved elsewhere.
- The Supabase MCP won't run `drop function`, and dropping needs the user's confirmation.
- A project is a top-level folder and a group is a folder inside one, so Drive mirrors `Sourcefold/<Project>/<Group>/…`. Migration `20261014010000_projects_and_groups.sql` makes links unique per group (`items_folder_canonical_url_key`), rejects sources saved directly in a project, and stops a group with sources from becoming a project. Projects share nothing: search, duplicate checks and recent X threads are scoped to one project.
- The desktop Connect button must be a plain form POST to `apps/web/src/app/desktop/connect/approve/route.ts`, which answers with a 303 to the loopback callback. A server action that called `redirect()` to `http://127.0.0.1:<port>` failed in the browser with "An unexpected response was received from the server".
- Local `npm run dev` uses the live Supabase project, so don't create or delete test data there without asking.
- Archiving (owner's choice, 2026-10-14) only hides a project. The owner first suggested deleting old projects from Supabase after 30 days and restoring them from Drive; we didn't, because links take about 1–2 KB each, and Drive would become the only copy of everything.
- Content lives in Drive (owner's decision, 2026-10-14): a Grokipedia article is about 200 KB of Markdown, so keeping text in Supabase would fill the 500 MB free database at a few thousand articles. Migration `20261014020000_content_lives_in_drive.sql` adds `mark_item_stored_in_drive`, which clears `markdown`/`storage_path` once the Drive copy exists. Renames and moves rebuild the file by downloading it from Drive. Notes and `x_posts` stay in Supabase. See SPEC section 4, "Where content lives".

- The desktop group view now matches the web's: a header with breadcrumb, serif title, source count and **New subgroup** / **Add image** / **New note**; a toolbar with **Select** and **Copy all links**; subgroup rows; and source rows with a colored type bar, type icon, source name, saved date and status check (source colors now match `docs/DESIGN.md`). New shortcuts, active when the source list has focus: `s` select mode, `Shift+Y` copy all links, `Shift+N` new subgroup, `i` add image (`c` new note already existed). **Add image** works in both modes. Offline, the `add_image` / `open_item_file` Rust commands save the file under the storage folder and open it in the system viewer. The desktop fetches pages in Rust (`src-tauri/src/substack.rs`, command `substack_fetch`), runs the extractor in the webview (`src/features/substack/substack-client.ts`) and saves through the normal `capture` path: to the web account when signed in, to disk offline. Owner's choice: only the desktop fetches Substack; the web app doesn't.

- Highlights (2026-10-17, contract `docs/handoff-highlights.md`): stored in `highlights` (Supabase, RLS; SQLite offline) and written into the source's `.md` as `## My highlights` before `## My note`. A trigger on `highlights` bumps `items.updated_at`, which is what makes Drive and the local copy rebuild the file; there is no other sync path. Both file builders strip the section before rebuilding, and the golden pair `item-with-highlights` pins the format for TypeScript and Rust. Offsets count the reader's rendered body text only, so anything that changes how the reader renders a body can orphan old highlights (they then show "Couldn't find this passage" in the panel; the prefix/suffix search usually recovers them). Reader keys live in `READER_COMMANDS` in the shortcuts registry, separate from `SHORTCUT_COMMANDS`, because the command palette runs every entry of the latter by id.
- Supabase's security advisor flags `acquire_drive_sync_lock`, `release_drive_sync_lock` and `save_google_refresh_token` as SECURITY DEFINER functions signed-in users can call. That's intended and safe: each one raises "not allowed" unless `p_user_id` is the caller's own id (or the caller is the service role), checked on the live database 2026-10-17. Don't revoke `execute` from `authenticated`: `POST /api/drive/save` calls them as the signed-in user.
- YouTube transcripts are English only (owner's choice, 2026-10-17). Videos with YouTube's AI auto-dubbing (The Economist, Dwarkesh) list one auto-generated caption track per dubbed language, sorted by language name, so "the first auto-generated track" was Arabic, Bangla or Dutch: 6 of the owner's 14 videos were saved that way. The original audio's track is `audioTracks[defaultAudioTrackIndex].captionTrackIndices[0]` (`tracks.ts`). Translation (`&tlang=en`) got a 429 on every try from the owner's connection while untranslated tracks came back 200, so it is a last resort: a refusal fails the row with its own message, not the rate-limit one. YouTube publishes no rate limit; blocks are per connection (cloud IPs nearly always). Add links leaves 2–5 s between videos and on a rate limit waits 1 min, then 3 min (`features/sources/youtube-pacing.ts`); after that the other videos stay Waiting until Retry.
